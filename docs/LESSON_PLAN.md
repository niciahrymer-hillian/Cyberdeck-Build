# 📖 Lesson Plan — Cyberdeck-Build

> **Chain K — Hardware & Systems Foundations** | A portable, handmade computer: Raspberry Pi + touchscreen + mini keyboard + battery in a custom enclosure.

## What This Project Is

Design and build a handmade portable computer around a Pi — power, display, input, enclosure, thermals — where every decision is yours.

## Learning Objectives

By the end I can:

1. Design a physical layout balancing ergonomics and internal space.
2. Calculate a **power budget** and size a battery for real runtime.
3. Select and configure a display with working drivers.
4. Choose input hardware suited to the form factor.
5. Assemble with durable wiring and adequate thermal management.
6. Configure the OS for a small screen.

## Software You Will Use

- Raspberry Pi OS.
- CAD or paper templates for the enclosure.
- Basic hand tools and a soldering iron.

## Build Order

1. Sketch the layout and mock it up at full size.
2. Calculate the power budget from measured draw.
3. Get the display working before committing to the enclosure.
4. Test the full stack loose on the bench.
5. Build the enclosure and mount everything.
6. Run it on battery and measure real endurance.

## Common Mistakes to Avoid

- Building the enclosure before confirming the electronics work.
- Underestimating power draw and getting an hour of runtime.
- No airflow, so the Pi throttles as soon as it is sealed.
- Wiring with no slack, so connectors stress and fail.
- Choosing a display with no driver support.

## Check Your Understanding

The quiz covers power budgeting, display selection, thermal management, and assembly order.

## Why This Matters (Industry Application)

Building custom hardware end to end demonstrates persistence and systems thinking in a way software alone
doesn't. Power budgets, physical constraints, and integration problems are real engineering, and the
finished object is a conversation piece that shows genuine curiosity.

## Reflection Questions

- What would you change in a second revision, and why did you only learn it by building?
- Where did a physical constraint force a decision software never would have?
